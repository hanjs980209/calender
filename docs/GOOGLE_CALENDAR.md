# Google Calendar 연결

하루 달력 0.2.0은 Google 계정의 **기본 캘린더(primary)**를 읽고 쓰는 기능을 제공합니다. 계정 로그인은 앱 내부 웹뷰 대신 기본 브라우저에서 진행합니다. 앱에는 공용 OAuth 클라이언트가 포함되어 있지 않으므로 아래 초기 설정이 한 번 필요합니다.

## 1. Google Cloud 설정

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 선택하거나 만듭니다.
2. **API 및 서비스 → 라이브러리**에서 **Google Calendar API**를 활성화합니다.
3. **Google Auth Platform**에서 앱 이름, 지원 이메일과 연락처를 설정합니다. 개인 Google 계정은 외부 사용자를 대상으로 설정하고, 테스트 상태라면 사용할 Google 계정을 테스트 사용자로 추가합니다. 메뉴 이름은 콘솔 버전에 따라 다를 수 있습니다.
4. 데이터 액세스에 `https://www.googleapis.com/auth/calendar.events` 범위를 추가합니다. 이 범위는 사용자가 접근 가능한 캘린더의 일정 조회·편집 권한입니다. 앱은 현재 기본 캘린더만 사용합니다.
5. **클라이언트 → 클라이언트 만들기 → 데스크톱 앱**을 선택합니다. 웹 애플리케이션이나 서비스 계정 유형은 지원하지 않습니다.
6. 클라이언트의 JSON 설정 파일을 다운로드합니다. `installed` 항목이 있는 원본 JSON을 사용하세요. 파일을 채팅이나 Git 저장소에 올리지 마세요.

개인 테스트 계정으로 사용할 때에도 Google 동의 화면이 표시됩니다. 테스트 상태의 외부 앱은 일반적으로 refresh token이 7일 후 만료되어 다시 로그인이 필요합니다. 다른 사용자에게 배포하려면 Google의 게시·검증 요건을 확인해야 합니다.

## 프로덕션 게시에 필요한 웹페이지

앱 이름과 이메일을 저장했어도 외부 OAuth 앱의 게시 버튼이 비활성화되고 브랜딩 구성을 완료하라는 안내가 나올 수 있습니다. 이때 프로덕션용 홈페이지·개인정보처리방침·이용약관 URL과 승인된 도메인 구성을 확인해야 합니다. 로고의 선택 여부와 웹페이지 게시 요건은 별개입니다.

Google 브랜딩에 입력할 사이트 주소는 다음과 같습니다. 각 페이지가 실제로 열리는 것을 확인한 뒤 입력하세요.

| 항목 | 주소 |
| --- | --- |
| 애플리케이션 홈페이지 | https://hanjs980209.github.io/calender/ |
| 개인정보처리방침 | https://hanjs980209.github.io/calender/privacy.html |
| 서비스 약관 | https://hanjs980209.github.io/calender/terms.html |
| 승인된 도메인 | `hanjs980209.github.io` |

Google Search Console에서 소유권 확인을 요구하면 **URL 접두어** 속성에 `https://hanjs980209.github.io/calender/`를 추가하세요. Google이 발급한 HTML 확인 파일을 사이트의 `docs/` 폴더에 배포하거나, HTML 메타 태그를 `docs/index.html`의 `<head>`에 추가한 뒤 확인할 수 있습니다. 확인 파일과 메타 태그는 공개용 소유권 증명이며 OAuth 인증 JSON·토큰과는 다릅니다. 현재 저장소에 Google의 확인 코드는 등록되어 있지 않습니다. 웹페이지 공개, Google Search Console에서의 소유권 확인, OAuth 앱 게시, Google의 브랜드·민감 범위 검증은 각각 별개 단계입니다.

참고: [Google OAuth 브랜딩 안내](https://support.google.com/cloud/answer/15549049), [동일한 게시 제한 문구 해결 사례](https://github.com/shitikanth/calibre-cloud/issues/147). 후자는 사용자 보고이며 개별 프로젝트의 Google 승인이나 검증 면제를 보장하지 않습니다. 게시 후 기존 테스트 토큰은 연결 해제 후 재로그인해 갱신하세요.

## 2. 앱 연결

1. Windows에서 `하루 달력.exe`를 실행합니다.
2. **설정 → Google Calendar 연결 → OAuth 설정 가져오기**로 다운로드한 JSON을 선택합니다.
3. **Google 로그인**을 눌러 기본 브라우저에서 계정을 선택하고 일정 권한을 허용합니다. 취소하거나 3분 안에 완료하지 못하면 다시 시도하세요.
4. 앱으로 돌아오면 기본 캘린더의 현재 화면 범위가 표시됩니다.

로그인은 PKCE와 무작위 state를 검증하는 `127.0.0.1`의 임시 포트 콜백을 사용합니다. Windows 방화벽이나 보안 도구가 로컬 콜백을 차단하면 로그인을 완료할 수 없습니다. 필요한 HTTPS 목적지는 `accounts.google.com`, `oauth2.googleapis.com`, `www.googleapis.com`입니다.

## 3. 다른 PC에서 이어 쓰기

다른 PC에도 최신 ZIP을 내려받아 전체 압축 해제하세요. 설정 JSON을 가져온 뒤 **같은 Google 계정으로 로그인**하면 Google에 저장된 일정이 나타납니다. 인증 토큰이나 암호화 저장 파일을 PC 간 복사하지 마세요.

- 날짜 선택 후 오른쪽 **Google 일정 +**로 종일 또는 시간 지정 일정을 등록합니다. 종료일은 화면에서 마지막 날짜를 포함하는 방식으로 입력합니다.
- 기존 로컬 메모는 **Google로 복사**를 누르고 제목·날짜를 확인한 뒤 **Google에 저장**합니다. 복사는 사용자가 저장을 누를 때만 발생하며 로컬 원본은 유지합니다.
- Google 일정의 **수정/삭제**는 실제 Google 캘린더와 다른 PC에도 반영됩니다. 반복 일정은 선택한 회차만 수정·삭제합니다.
- 화면에 표시된 일정은 1분마다, 월을 이동하거나 앱을 다시 열 때 조회합니다. **지금 새로고침**으로 즉시 확인할 수 있습니다. Google 웹에서 바꾼 내용을 받으려면 새로고침하세요.
- 여러 PC에서 같은 일정을 수정하면 etag로 변경 충돌을 감지합니다. 오류가 표시되면 새로고침한 후 다시 수정하세요.
- 연결 해제는 이 PC에 저장된 인증 토큰만 삭제하며 Google 일정은 지우지 않습니다. Google 계정의 연결된 앱 설정에서 권한 자체를 철회할 수 있습니다.

로컬 메모의 체크 완료·메모 색상과 앱의 투명도·월요일 시작 설정은 PC별로 유지됩니다. Google 일정과 로컬 메모는 별도 데이터이며 자동으로 서로 덮어쓰지 않습니다.

오프라인에서는 로컬 메모를 계속 쓸 수 있습니다. Google 일정 쓰기는 연결이 필요하고 오프라인 전송 대기열은 없습니다. 실패 시 편집창은 유지되며 재시도할 수 있습니다. 등록 요청의 고정 ID로 중복 생성을 방지합니다. 타임아웃 후 이미 저장되었다는 안내가 나오면 편집창을 닫고 새로고침해 확인하세요.

## 4. ChatGPT에서 일정 묻기

ChatGPT 설정의 앱/연결 메뉴에서 Google Calendar 연결을 사용할 수 있다면, 동일한 Google 계정을 별도로 연결하세요. 이후 ‘이번 주 일정 알려줘’처럼 요청할 수 있습니다. 위젯 로그인만으로 ChatGPT 연결이 자동 설정되지는 않으며, 사용 중인 ChatGPT 계정에서 해당 연결 기능이 제공되어야 합니다.

## 저장과 검증 범위

OAuth 클라이언트 설정과 인증 토큰은 Electron 사용자 데이터 폴더의 `google-account.enc`에 운영체제 `safeStorage`로 암호화 저장합니다. Windows에서는 DPAPI를 사용합니다. 인증 파일은 일반 메모 백업이나 배포 ZIP에 포함되지 않습니다. 원본 JSON은 선택한 위치에 그대로 있으므로 별도 보관하세요. 토큰을 화면이나 로그에 출력하지 않습니다.

API/인증 테스트는 모의 응답, UI 테스트는 모의 Electron IPC를 사용합니다. 실제 Google 계정 OAuth 동의, Calendar API 요청, Windows 암호화 저장소·브라우저 콜백은 사용자 설정 후 Windows에서 검증해야 합니다.
